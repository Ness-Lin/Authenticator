## 1. 设计基线与决策等级

### 1.1 已有工程事实

当前应用为单模块 `:app` 的 Kotlin/Compose 工程，业务模块尚未建立。本次读取到的构建配置为 Kotlin 2.2.10、AGP 9.3.2、Compose BOM 2026.02.01，minSdk 24、targetSdk 36、compileSdk 36.1、Java 编译兼容级别 11。以上只是仓库声明，不表示已验证依赖可解析、构建工具兼容或编译成功。

本文不升级上述版本，不修改现有代码，也不将拟选依赖描述为已接入。实施前需完成 Gradle、AGP、JDK、Kotlin、KSP 的兼容性构建验证，运行 Gradle 的 JDK 与 Java 字节码目标不是同一概念。

### 1.2 范围约束

必须实现离线 TOTP、扫码/手动添加、列表自动更新与复制、账户搜索/编辑/删除、安全导出、本地加密和默认应用锁。遵循需求中的算法、位数、周期、密钥长度和输入大小限制。

不实现 HOTP 账户、厂商推送审批、私有批量迁移、云同步、应用内备份恢复、图库扫描或跨平台客户端。HOTP 仅作为 TOTP 计算所需的算法基础，不开放计数器账户功能。

### 1.3 决策解释

- 强制约束：来源于需求与开发规范，实施不得静默改变。
- 本文设计：模块归属、接口和状态机采用本文方案，评审通过后作为实施基线。
- 待验证选型：新增库的确切版本、API 兼容性和性能必须先验证再锁定。
- 产品待确认：首版不支持文件恢复、默认应用锁和明文导出策略仍沿用需求初稿的评审状态。

若技术验证无法满足 minSdk、安全要求或导出字节协议，应提出方案修订，而不是运行时静默降级算法、取消加密或改变文件格式。

## 2. 系统结构与模块清单

### 2.1 分层结构

```text
:app                         Android 宿主与唯一依赖装配根
:common:basic                可移植基础类型
:arch:api                    Repo、访问控制、时间、加密、编码、输出契约
:arch:impl                   公共能力实现及 Android 平台适配
:arch:ui                     公共主题、组件与系统 UI 适配
:feature:token:api           验证码、账户列表操作、配置解析接口
:feature:token:impl          TOTP、账户操作与 URI 业务规则
:feature:token:ui            列表、搜索、详情、编辑和删除确认
:feature:enrollment:api      添加流程与校验结果接口
:feature:enrollment:impl     添加校验、重复检测与提交
:feature:enrollment:ui       扫描、手动输入与添加确认
:feature:transfer:api        导出请求、状态、结果接口
:feature:transfer:impl       导出快照、格式与加密编排
:feature:transfer:ui         选择、风险确认、口令和文件创建交互
:feature:security:api        应用锁、认证与操作授权接口
:feature:security:impl       会话与操作授权策略
:feature:security:ui         锁定页面及认证流程展示
```

首版必需 17 个 Gradle 模块，每个功能均有真实的 api、impl、ui 职责。工具模块不再无意义细分。

条件模块为 `:feature:settings:api/impl/ui`：仅在确认独立设置页面后创建。首版没有已确认的用户可调偏好，不为了“设置”提前增加开关。当前隐私说明由 arch:ui 资源组件在首页/导出流程展示；关于和设置页面不是 MVP 的硬性前置。

### 2.3 编译依赖与运行时调用

依赖方向使用 `A → B` 表示 A 编译依赖 B：

```text
common:basic → Kotlin 基础库
arch:api → common:basic
arch:impl → arch:api, common:basic
arch:ui → arch:api, common:basic
feature:X:api → arch:api, common:basic
feature:X:impl → 自身 api, 必需的其他 feature api, arch:api
feature:X:ui → 自身 api, 必需的其他 feature api, arch:api/ui
app:wiring → 各 impl 的装配工厂 + api
app:navigation → 各 ui 的入口 + api
```

具体跨功能依赖白名单：

| 调用方 | 额外允许的功能 api | 原因 |
| --- | --- | --- |
| token:impl | security:api | 会话校验及前台生成资格 |
| enrollment:impl | token:api、security:api | 解析配置、校验保存授权 |
| transfer:impl | token:api、security:api | 规范 URI 输出和导出授权 |
| security:impl | 无 | 安全机制仅依赖 arch:api |
| enrollment:ui | security:api（需要时） | 认证入口状态 |
| transfer:ui | security:api | 主动发起重新认证 |
| token:ui | security:api（需要时） | 锁定反馈，不挂载其他 feature 页面 |

功能 api 之间不相互依赖；共享参数类型下沉 arch:api，领域专有结果由各功能拥有。禁止 impl→impl、ui→impl、feature ui→其他 feature ui 和 arch→feature。app 中只有 wiring 包可引用 impl 工厂，工厂返回接口，业务实现默认 internal。

运行时对象链可以为 `transfer:impl → SecuritySession 接口 → security:impl`，这不产生实现层之间的编译依赖。Room Repo 只认识 arch:api 的访问门禁，不反向依赖 security:api。

## 3. 技术选型与平台兼容

| 能力 | 选型 | 依据与实施约束 |
| --- | --- | --- |
| UI | Jetpack Compose + Material 3 | 复用工程基础，声明式状态、系统主题与无障碍支持 |
| 页面状态 | ViewModel + StateFlow + collectAsStateWithLifecycle | 生命周期清晰；不使用全局事件流 |
| 并发 | kotlinx.coroutines、注入 Dispatcher | 支持可测试调度与后续 KMP；取消可追踪 |
| 依赖注入 | 手动构造注入、app AppGraph | 当前模块数量可控，避免 DI 注解污染 api；工厂隔离 internal 实现 |
| 导航 | AndroidX Navigation Compose，宿主统一注册 | 系统返回栈、非敏感参数；feature 间通过回调请求导航 |
| 扫码相机 | CameraX Preview/ImageAnalysis | 生命周期绑定、背压控制、手电筒支持 |
| QR 识别 | ZXing core，仅 QR_CODE | 离线运行，无模型下载或 Google Play 服务依赖；直接消费亮度帧 |
| 存储 | Room + KSP，单数据库 | 事务、迁移与测试成熟；数据库仅存密文和最小元数据 |
| 偏好存储 | 有需求后引入 DataStore | 只存非敏感偏好，不提前增加依赖 |
| 本地加密 | Android Keystore + JCA AES/GCM/NoPadding | API 24 可用，密钥不可导出；硬件能力不作统一保证 |
| HMAC | JCA Mac，SHA1/SHA256/SHA512 | 成熟提供方，不手写密码学原语 |
| 导出 KDF | Bouncy Castle 轻量级 PBKDF2-HMAC-SHA256 API | 显式接收 UTF-8 字节；避免 API 24–25 平台算法可用性及字符转换差异 |
| 导出 AES-GCM | JCA，导出临时派生密钥 | 与本机 Keystore 解耦，满足跨设备格式 |
| JSON | kotlinx.serialization | 显式 DTO/schema，适合后续共享；不自动将领域模型序列化 |
| Base32 | Apache Commons Codec Base32 严格模式 + 输入规则校验 | 通用编码能力在 arch:impl；严格填充/尾位须补充契约测试 |
| URI | arch 内 java.net.URI 结构解析适配 | 使用 raw path/query 保留编码与重复参数；不把 JVM 类型暴露到 api |
| 系统认证 | AndroidX Biometric + 系统设备凭据 | API 分支兼容，取消与锁定反馈明确 |
| 文件输出 | SAF ACTION_CREATE_DOCUMENT + ContentResolver | 不请求广泛存储权限，由用户选择文件提供方 |
| 测试 | JUnit、coroutines-test、Room 测试、Compose UI、Macrobenchmark | 分离算法、存储、系统流程及性能验证 |
| 静态检查 | Android Lint、ktlint/detekt、Gradle 依赖约束任务 | 代码风格、资源文案、依赖边界与敏感路径检查 |

新增依赖均为设计选型，确切版本在接入验证后固定在 libs.versions.toml。特别检查 BC 构件在 minSdk 24、R8、包冲突和许可证上的可用性；不通过全局注册 Provider 替换系统密码提供方，仅使用所需轻量级 API。若构件不兼容，必须评审另一个成熟、字节语义相同的实现，不能手写 PBKDF2 或改变格式。

ZXing、Commons Codec 和 URI 实现均为 JVM 内部适配；KMP 时替换适配而非假称这些实现可以原样进入 commonMain。库默认“宽松模式”不得当作产品安全校验器。

## 4. 数据模型与存储协议

### 4.1 模型归属

| 类型 | 所属 api | 字段和规则 |
| --- | --- | --- |
| AccountId | arch:api | UUID 规范小写文本，生成后不变，不含账户信息 |
| OtpAlgorithm | arch:api | SHA1、SHA256、SHA512 枚举；显示名由 UI 资源映射 |
| AccountSummary | arch:api | id、issuer、accountName、createdAtEpochMillis；仅在解锁会话内可用 |
| OtpParameters | arch:api | algorithm、digits、periodSeconds；验证后不可变 |
| SensitiveAccount | arch:api | 摘要、参数和受控密钥字节；非 data class，禁止默认序列化 |
| SecretBytes / PasswordBytes | arch:api | 受控字节缓冲区，脱敏 toString，用后清零，不允许持久化状态框架保存 |
| AccessLease | arch:api | 不透明能力句柄；对象本身不是授权证据，必须向门禁验证 |
| OperationBinding | arch:api | 操作类型、排序后的账户 ID、格式、请求 ID、可选目标引用 |
| GeneratedCode | token:api | accountId、ASCII digits、validFromEpochMillis、validUntilEpochMillis |
| EnrollmentDraftId | enrollment:api | 仅内存草稿引用，不携带共享密钥 |
| ExportRequestId | transfer:api | 单次导出流程 ID，不代表已授权 |

时间公共签名使用语义明确的 Long 毫秒/秒字段，避免 java.time 类型泄漏；平台转换及 RFC 3339 格式化经 arch 能力完成。UUID、时间和协议编码工具实现归 arch:impl。

含密钥对象不实现 Parcelable、Serializable，不放到导航序列化模型。ByteArray 必须进行所有权约束，外部返回副本或作用域内借用；Kotlin 类型本身无法禁止恶意复制，需要代码审查和测试共同约束。

### 4.2 Room 表设计

表 `encrypted_accounts`：

| 列 | 类型 | 约束/作用 |
| --- | --- | --- |
| record_id | TEXT | 主键，AccountId |
| schema_version | INTEGER | 本地加密负载版本，初始 1 |
| key_version | INTEGER | Keystore 别名版本，初始 1 |
| revision | INTEGER | 从 1 开始，更新时递增，用于并发检查 |
| nonce | BLOB | 12 字节随机数 |
| ciphertext | BLOB | AES-GCM 密文拼接 16 字节认证标签 |

不保存明文名称、发行方、密钥、算法、创建时间或密钥指纹。记录数量、UUID、修订次数、长度和访问模式不属于隐藏承诺。

加密负载含 id、issuer、accountName、type、secret、algorithm、digits、period、createdAt，使用独立的本地 DTO，不能与导出 DTO 共用以免升级耦合。解密后校验内部 id 等于外层主键。

本地 v1 AAD 精确采用 ASCII：`authenticator-record:v1|{recordId}|{keyVersion}|{revision}`，整数使用无前导零十进制；schemaVersion 必须为 1。AAD 构造集中定义并固定测试。此方案阻止跨记录/版本混用，但不声称能防止攻击者回滚整个有效数据库快照。

nonce 由 SecureRandom 产生，每次新增或重加密都生成新值；可在 `(key_version, nonce)` 上建唯一索引拒绝当前存量碰撞，发生碰撞重新生成。历史版本删除后仍依赖 96 位安全随机数的低碰撞概率；不能将这一机制宣传为数学上的全历史唯一保证。

### 4.3 Repo 行为

- 初始打开数据库不等于解锁；订阅和读取均经过 AccessGate。
- 列表订阅只发布摘要。需要验证码时按 ID 批量解密配置，结束后释放敏感缓冲区；不在每个一秒 tick 重读全部密钥。
- 为有效区间保留验证码和非敏感周期缓存，密钥不放入全局长期缓存；代码本身也在锁定时清除。
- 排序为 createdAt 升序、id 升序，创建时间被加密，解锁后在内存排序。
- 所有写入、重复检测和快照选择通过同一 Repo 写互斥控制，Room 事务保证落库一致性。不持有数据库事务等待相机、系统认证、口令或文件提供方。
- 重复比较规范密钥字节、算法、位数和周期；不持久化易于离线关联的密钥哈希索引。最多 1000 条时可受控解密扫描比较，短生命周期处理。
- 导出先在短只读事务读取指定账户的密文版本，事务结束后解密。若缺少任意选中 ID，则整体返回 SelectionChanged，不悄悄少导出。
- 重命名使用 expectedRevision 防止覆盖并发变更；删除返回明确 NotFound/Conflict，不将未知记录删除假报为成功。
- 修改失败保持原密文，成功后发布摘要变化；不发布原始密钥变更事件。
- 区分首次无密钥与已有记录但 Keystore 丢失：后者进入不可解密状态，禁止自动创建新密钥替代旧数据。
- Room migration 显式编写；需要重加密的升级在解锁后执行，支持失败回滚，不使用 destructive migration。

## 5. 模块实现方案

### 5.1 common:basic、arch 三层与 app

common:basic 仅放真正复用的结果容器等基础定义；业务错误仍归本功能。arch:api 的接口供功能消费，arch:impl 以工厂创建 Repo、CryptoProvider、EncodingCodec、Clock、AccessGate 和文件输出适配器。

app 建立应用级 AppGraph，注入平台对象；认证 Activity 桥按宿主生命周期绑定，不能由应用级对象永久持有 Activity。ViewModel 工厂只接受 api 接口。会话作用域在锁定时取消，页面作用域由 ViewModel 管理。

arch:ui 提供主题、错误容器、确认弹窗、密码表单组件及系统交互宿主；这些公共组件只接收值、资源和回调，不注入功能实现。系统认证与文件选择器由宿主协调，不能通过全局 emitter 请求弹窗。

### 5.2 token：解析、生成和账户操作

#### 5.2.1 TOTP 算法

输入为已验证配置和 UTC 时间，计算路径：

1. `epochSeconds = floor(epochMillis / 1000)`，拒绝 1970 年以前的设备时间并提示检查设置。
2. `counter = floor(epochSeconds / periodSeconds)`，编码为 8 字节大端无符号计数器表达。
3. 用 CryptoProvider 计算对应算法 HMAC，token:impl 不自行编写 HMAC。
4. `offset = digest[last] & 0x0f`，取 offset 开始的 4 字节，首字节与 `0x7f` 相与，再按大端拼成 31 位正整数。
5. 对 `10^digits` 取模，左侧补 ASCII 0 至 6 或 8 位。
6. 返回 `[counter * period, (counter + 1) * period)` 有效区间，以毫秒表示。
7. 倒计时为 `ceil((validUntil - now) / 1000)`；正好边界处展示新代码及完整周期，不显示旧代码可点击状态。

SHA-1/256/512 分别使用摘要最后一字节获取 offset；禁止将 SHA-1 的固定摘要长度假设套用到其他算法。

#### 5.2.2 时钟与更新

只有一个会话内前台 ticker，按下一个整秒边界调度，delay 仅用于唤醒，每次均读取真实 Clock。系统时间广播适配在 arch 中维护自己的时钟状态，属于专用可观察能力，不是通用事件总线。

ViewModel 将可见账户 ID 作为显式请求交给用例；按周期边界批量计算，非边界 tick 只更新倒计时。快速滚动时为新进入可见区的账户取码。账户列表变化、时钟改变、前台恢复触发失效和重新计算。过期结果不得覆盖新结果，使用请求序号或 collectLatest 丢弃旧批次。

复制操作调用 `currentCode(id)` 并验证会话及时间，不直接复制 Composable 缓存。结果返回到剪贴板前再次检查有效期，已过期则重取。剪贴板写入包含随机所有权标记，延迟清除时同时验证标记与当前条目，避免清除之后碰巧相同数字的用户内容。

#### 5.2.3 URI 与 Base32

- arch:impl 负责结构化 URI 拆解及百分号解码，token:impl 负责 otpauth 业务解释。
- 限制 UTF-8 总字节数不超过 8 KiB；拒绝 userInfo、端口、fragment、错误 authority 和编码，避免含混的认证配置。
- 查询参数保留为有序键值列表，不能先转 Map 丢失重复键；解码后检查重复的已知参数。
- 路径和参数严格 UTF-8 解码一次，`+` 保留为加号；不使用表单 URLDecoder 的加号转空格语义。
- 支持的参数名为文档规定的小写形式；算法值统一映射为已知枚举，不支持的值明确拒绝。
- label 第一个解码后的冒号作为发行方分隔；issuer 一致性检查使用同一 trim 策略，不进行隐式 Unicode 规范化。
- 手动密钥允许移除空格/连字符；二维码密钥只接受合法 Base32 与正确填充，不把任意破损字符静默清洗掉。
- 严格校验填充位置、合法字符、尾位和解码长度；10–15 字节产生需确认的安全警告，16–128 字节正常，其他拒绝。
- 业务规则统一由配置验证器执行，扫描与手动路径不得产生两套参数校验。

URI 输出采用同一字段映射，label 及参数正确百分号编码，不使用字符串拼接替代编码。发行方或账户名包含冒号时，otpauth label 的语义存在歧义：首版规范输出需拒绝无法无歧义回读的名称组合，并提示修改名称或改用加密导出；此为兼容导出的显式限制，不影响账户保存。必须覆盖无发行方但账户名含冒号等回读测试，不能声称百分号编码能消除解码后的分隔歧义。

### 5.3 enrollment：扫码、手动输入与确认

扫描页使用 CameraX Preview 与 ImageAnalysis，策略 KEEP_ONLY_LATEST，后台单线程解码 QR_CODE。优先使用亮度平面，正确处理 rowStride、pixelStride 和 rotationDegrees，不把整帧转 Bitmap 引入持续分配。所有成功、失败和取消分支均关闭 ImageProxy。

扫描命中后用原子标记暂停分析，交给 EnrollmentService 创建内存草稿。错误时显示资源文案并允许重扫，成功后在同一 enrollment 页面作用域内切换确认状态，不将原始 URI 或密钥放入导航参数。必要的扫码中间对象只在页面内存中存在。

手动页字段与默认值完全遵循需求：发行方 128 码点、账户名 256 码点、算法默认 SHA1、6 位、30 秒。码点计数不能简单使用 UTF-16 String.length。字段校验错误为类型化结果，UI 映射资源。

流程状态：`Editing/Scanning → Validating → ReadyToConfirm → Saving → Completed`。字段错误返回 Editing；短密钥警告与重复配置分别显示确认。草稿绑定会话，锁定后失效；提交只传草稿句柄和确认选择，不再次信任任意 UI 配置。

为防止 TOCTOU，最终保存时重新检查重复。若检查结果已变化，返回新的重复确认挑战；不能只凭早先 UI 上的“无重复”继续插入。确认绑定草稿版本与重复集合，提交后一次性消费，连续点击不得新增两条。

首版相机拒绝时可转手动输入；仅点击扫描才申请权限，永久拒绝提供设置入口。后台停止相机、清理草稿中的密钥，返回后认证并重新输入/扫描。旋转不等同于进入后台，可由 ViewModel 暂存表单，但不能持久化到系统状态。

### 5.4 security：会话、系统认证和授权

#### 5.4.1 应用锁与底层门禁分工

security:impl 负责何时需要认证、如何消费授权、如何锁定；arch:impl 的 AccessGate 负责令牌登记/验证与 Repo 门禁。两者通过 arch:api 协作，arch 不导入 security。

平台认证桥由 arch:api 定义，arch:ui 绑定 BiometricPrompt/设备凭据交互，可信的认证结果通过该桥回到已发起的请求。页面不能调用 `setAuthenticated(true)`。成功回调必须对应当前未完成请求、宿主实例和会话 generation，过期或重复回调被丢弃。

令牌仅为进程内能力，不防御同进程恶意代码或已被攻陷系统。对象不可序列化；AccessGate 验证其服务端登记状态，而不是相信客户端字段。

#### 5.4.2 状态机

| 状态 | 进入条件 | 允许操作 |
| --- | --- | --- |
| Locked | 冷启动、后台、主动锁定、认证过期 | 仅展示锁定/引导内容 |
| Authenticating | 用户发起有效系统认证 | 等待结果，不读取账户明文 |
| Unlocked | 当前请求系统认证成功 | 账户列表、添加/编辑/删除、取码 |
| Unavailable | 未设安全锁屏或平台认证不可用 | 引导设置，不保存密钥 |
| StorageUnavailable | 密钥失效/密文不可解密 | 显示恢复说明，不覆盖数据库 |

进入后台首先隐藏敏感视图、撤销会话和操作授权，再取消相关协程、关闭敏感资源。Activity 配置变更不创建新后台会话；用宿主实际前后台状态识别，不能仅依赖带延迟的进程生命周期回调实现“立即遮挡”。系统认证弹窗占用交互不应误判为普通外部跳转；设备凭据的受控请求只能完成其绑定的认证，不能保活旧会话。

API 30+ 使用经验证的 BIOMETRIC_STRONG/DEVICE_CREDENTIAL 组合。API 24–29 通过 AndroidX Biometric 与系统凭据回退路径分别实现，不假定所有版本支持相同 allowedAuthenticators 组合；无生物信息时允许安全锁屏凭据，无安全锁屏则进入 Unavailable。

#### 5.4.3 操作授权

应用会话 Lease 可用于普通读写；每次导出必须获得新的 Export Lease。Export Lease 绑定 requestId、会话 generation、账户 ID 集合、格式与目标引用，单次消费。选择、格式或目标改变即重新授权。

拟定未使用 Export Lease 有效期为 120 秒，用单调时钟衡量，不能用可被手动修改的墙上时间。消费后转为该次导出的执行授权，完成、失败、取消或后台即撤销；不得让长 KDF 单纯因起始令牌过期而任意中断，但必须持续响应后台撤销。

Repo 和用例双重检查门禁。异步结果发布及写入外部目标前再次确认 generation；已撤销会话的结果不更新 UI。不承诺能撤回锁定前已写给外部提供方的字节。

### 5.5 transfer：导出状态机与格式

#### 5.5.1 状态机和 SAF 返回

```text
Selecting → ReviewingRisk → Authenticating → EnteringPassword
          → ChoosingDestination → LockedAwaitingReturn
          → Reauthenticating → ReenteringPassword
          → PreparingSnapshot → DerivingKey → Encrypting → Writing
          → Completed / Failed / Cancelled
```

明文模式跳过口令步骤，但不跳过风险确认和认证。选择器取消则结束本次请求，不生成文件内容。

需求要求选择目标之前认证/输入口令，同时要求后台锁定。本文采用保守实现：启动 SAF 前清除口令和敏感草稿，仅保留 ID、格式、请求 ID 等非敏感流程信息；选择器返回后重新认证，加密模式重新输入口令。UI 应以资源说明“返回后需要重新验证”，不能以避免多次操作为由使旧授权跨后台存活。

目标 Uri 仅在平台流程控制器中短暂持有，并以不透明 OutputTarget 引用提供给用例；不写入业务模型或持久化导航状态。进程死亡取消导出，已创建的空文件在可访问时尽力删除；无权限或无目标引用时提示用户检查位置，不保留额外长期文件权限。

写入期间用户转后台：撤销授权、取消作业、关闭输出并尽力删除残留。对于提供方已写/同步的部分字节，不宣称可以彻底撤销。

#### 5.5.2 加密导出步骤

1. 确认至少 1 条且最多 1000 条，校验选择无重复、格式和目标与授权匹配。
2. 消费 Export Lease，获取一致密文快照并在作用域内解密；验证全部账户可导出。
3. 序列化独立 BackupPayloadV1 DTO，所有账户元信息位于负载内部。
4. 将口令按 UTF-8 严格转换，不 trim、不做 Unicode 规范化；验证 12–128 码点和两次完全一致。
5. SecureRandom 产生 16 字节 salt 和 12 字节 nonce，PBKDF2-HMAC-SHA256 执行 600000 次并派生 32 字节。
6. 使用 AES-256-GCM、128 位标签、ASCII AAD `authenticator-backup:v1` 加密负载。
7. 组装外层 JSON；ciphertext 为密文紧跟认证标签后进行标准有填充 Base64 编码，字段定义完全遵循需求第 4.3 节。
8. 验证最终 UTF-8 文件不超过 10 MiB；超限返回 TooLarge，不向目标写入部分有效文件。
9. 检查授权后打开输出、写入、flush（提供方支持时）、关闭。关闭成功才返回 Completed；这表示提供方接受写入，不保证云端同步完成。
10. finally 清理口令字节、派生密钥、明文负载、账户配置及中间缓冲区。

最多 1000 条、10 MiB 文件允许首版在受控后台任务中完成有限内存序列化；必须测试峰值内存，多份字符串/Base64 会增加开销。不创建磁盘明文临时文件。若后续改为流式加密，仍需确保尾部标签、大小限制、取消与成功语义一致。

JSON 字段名、格式标识和算法名为非本地化协议常量。外层结构为需求规定的 format/version/kdf/cipher/ciphertext；不添加账户数量或设备 ID。exportedAt/createdAt 输出 UTC RFC 3339，issuer 缺失统一输出空字符串；不遗漏必需字段。

当前产品不读取备份文件，但测试解码器需在 KDF 前严格限制 10 MiB、版本和参数，并检测重复 JSON 字段。kotlinx.serialization 的普通解码成功不代表已满足重复键拒绝要求；采用可报告重复键的流式校验步骤或独立测试解析器验证，后续产品恢复器不得直接依赖覆盖式 Map 解析。

#### 5.5.3 明文导出

使用 token:api 的规范 URI 序列化能力逐条输出，UTF-8、无 BOM、LF 分隔，文件末尾固定保留一个 LF；每条包含 secret、algorithm、digits、period，issuer 非空时包含 issuer。先验证所有选中账户都可无歧义输出，再开始外部写入。

不导出当前验证码，不生成二维码图片，不提供自动分享。文件默认名采用不含账户信息的机器格式，例如固定前缀加 UTC 时间；文件扩展名及 MIME 由协议常量定义。

### 5.6 UI、资源与可访问性

首页直接为账户列表，工具栏有添加、搜索和导出入口；编辑/删除位于账户操作菜单。扫描页具备手电筒、取消与手动输入入口。错误、空状态、加载、锁定和正在导出均为独立状态，不显示假数据。

所有生产 UI 和 Preview 文本均来自对应 ui 模块资源，默认 values 完整简体中文、values-en 完整英文。错误结果映射到资源 ID 的代码只存在 UI 层。数量使用 plurals，句子使用位置占位符，不把资源 ID 放入 api。

敏感页启用 FLAG_SECURE；Activity 在内容建立前设置防护，避免首帧泄漏。触控至少 48 dp，正文对比度至少 4.5:1，320 dp 与 200% 字体下允许换行，LazyColumn 使用稳定 ID。倒计时不使用逐秒无障碍实时播报，验证码仅在主动操作时读出。

密码表单使用安全输入配置，不使用 rememberSaveable；平台不支持某项输入法防护时记录限制，不声称能约束恶意输入法。剪贴板仅保存短时验证码，Android 版本允许时添加敏感标记；尽力清除，不保证进程死亡后仍可执行定时清理。

## 6. 模块间接口设计

### 6.1 接口基础规范

- 进程内采用 Kotlin 接口调用和结构化协程，无 HTTP、IPC 或消息总线协议。
- 单次命令为 suspend 函数，持续状态为只读 Flow/StateFlow；MutableStateFlow 留在实现内部。
- 预期失败用类型化结果表达，取消抛出 CancellationException；不得将取消捕获为普通 Failure 或 Success。
- api 模型不引用 Android、Room、Compose、R、第三方 SDK 或其他 feature api 类型。
- 每个 suspend 方法都必须注明线程安全、幂等性、取消点和敏感缓冲区所有权。
- 实现通过构造注入；不得使用全局容器或强转接口获取实现。

以下为契约级 Kotlin 草案，只定义边界与调用形状，辅助类型按本文数据字典实现，不代表可直接编译的完整源码。

### 6.2 arch:api 契约

```kotlin
interface Clock {
    fun epochMillis(): Long
    fun monotonicMillis(): Long
}

interface AccessGate {
    fun isValid(lease: AccessLease, binding: OperationBinding): Boolean
    fun revokeAll()
}

interface AccountRepository {
    fun observeSummaries(lease: AccessLease): Flow<AccountReadState>
    suspend fun insert(request: AccountInsert, lease: AccessLease): StoreResult
    suspend fun rename(request: AccountRename, lease: AccessLease): StoreResult
    suspend fun delete(request: AccountDelete, lease: AccessLease): StoreResult
    suspend fun openSnapshot(
        ids: Set<AccountId>,
        lease: AccessLease
    ): SnapshotResult
}

interface SensitiveSnapshot {
    val accounts: List<SensitiveAccount>
    fun close()
}

interface OutputTarget {
    val reference: OutputReference
    suspend fun open(): OutputOpenResult
    suspend fun deletePartial(): CleanupResult
}

interface OutputSession {
    suspend fun write(bytes: ByteArray, offset: Int, count: Int)
    suspend fun finish()
    suspend fun abort()
}
```

SnapshotResult 成功返回受控快照，由调用者在 finally 中 close；不得跨 UI 状态、Flow 或导航发布。接口不是向 UI 开放任意密钥查询的许可：只有用例层访问 Repo，UI 通过功能接口获取摘要或验证码。锁定时 observeSummaries 发布 Locked 并清除旧摘要，不能只停止刷新而让 StateFlow 保留明文。

OutputSession.finish 包含最终 flush/close，失败需抛出/映射为写入错误；abort 负责关闭而不代表文件删除，调用方另行 deletePartial。实现仅封装流和清理能力，不解释导出 schema。

CryptoProvider 应提供以下精确能力，不将密钥类型混在一个万能字符串接口里：

| 方法能力 | 输入 | 输出/约束 |
| --- | --- | --- |
| hmac | 算法枚举、SecretBytes、消息字节 | 摘要字节；调用者清理 |
| deriveExportKey | PasswordBytes、16 字节 salt、固定 v1 参数 | 32 字节敏感密钥；UTF-8 语义明确 |
| encryptExport | 临时密钥、nonce、AAD、明文 | 密文及标签 |
| encryptRecord/decryptRecord | Keystore keyVersion、nonce、AAD、负载 | 不暴露 Keystore 密钥字节 |
| randomBytes | 经允许的长度 | 安全随机数据，测试可注入确定性来源 |

SecureStorage 是 arch 的加密记录存取端口，供 Repo 内部组合使用；其签名只涉及 RecordEnvelope、事务和版本，不重复定义账户搜索/重复等业务操作。

### 6.3 token:api 契约

```kotlin
interface OtpConfigurationParser {
    fun parseUri(raw: String): ConfigurationResult
    fun validateManual(input: ManualConfiguration): ConfigurationResult
    fun encodeUri(account: SensitiveAccount): UriEncodingResult
}

interface TokenService {
    fun observeAccounts(query: String): Flow<AccountListState>
    suspend fun codes(ids: Set<AccountId>): CodeBatchResult
    suspend fun currentCode(id: AccountId): CodeResult
    suspend fun rename(request: RenameAccount): AccountActionResult
    suspend fun delete(request: DeleteAccount): AccountActionResult
}
```

服务内部获取并验证当前会话；调用者不能指定伪造时间去展示“有效”验证码。底层纯 TOTP 计算函数接受注入时间用于单元测试。ConfigurationResult 的成功值含敏感配置，生命周期由 enrollment:impl 消费控制，不直接发布到 token UI。

encodeUri 仅供受控导出用例使用，返回字符串含密钥，必须被视为敏感明文，不作日志或持久化状态。批量取码支持部分记录错误，但锁定为整批失败；损坏账户不生成随机或默认代码。

### 6.4 enrollment:api 契约

```kotlin
interface EnrollmentService {
    suspend fun prepareManual(input: ManualEnrollment): PreparationResult
    suspend fun prepareQr(raw: String): PreparationResult
    suspend fun confirm(request: ConfirmEnrollment): EnrollmentResult
    fun discard(draftId: EnrollmentDraftId)
}
```

PreparationResult 只向 UI 暴露草稿 ID、摘要、参数与字段/风险信息，不返回密钥。需要用户显式查看扫描密钥时，通过受控短时揭示操作返回到本页敏感字段，关闭确认页即释放；该扩展不能变成通用后台密钥读取接口。

ConfirmEnrollment 含 draftId、草稿 revision、短密钥确认和重复挑战 ID。挑战在 impl 内保存并绑定会话，UI 单独传布尔值不能绕过“实际展示哪条记录的风险”校验。失败枚举至少包括 InvalidField、WeakSecretConfirmationRequired、DuplicateConfirmationRequired、DraftExpired、Locked、StorageFailure。

### 6.5 security:api 契约

```kotlin
interface SecuritySession {
    val state: StateFlow<LockState>
    suspend fun unlock(): AuthenticationResult
    suspend fun authorizeExport(binding: OperationBinding): AuthorizationResult
    fun lock(reason: LockReason)
}
```

AuthorizationResult 成功值为 arch:api 的 AccessLease，因此 transfer:api 无需引用 security:api。授权由系统认证桥完成，业务 UI 不能直接构造有效 Lease。后台锁定同步撤销 generation，异步清理不能延迟授权失效。

### 6.6 transfer:api 契约

```kotlin
interface ExportService {
    suspend fun execute(
        request: ExportRequest,
        target: OutputTarget,
        lease: AccessLease,
        password: PasswordBytes?
    ): ExportResult
}
```

ExportRequest 包含 requestId、选中 ID 集合、格式及风险确认记录。加密模式必须有 password，明文必须没有；后端仍校验，不能只依赖页面隐藏输入框。execute 在同一请求上最多允许一次正在执行，重试使用新的请求和授权。服务对 password 的所有权为消费型，方法返回或取消后负责清理；UI 不再持有可用副本。

阶段进度可通过请求级只读状态对象观察，禁止全局进度事件通道。阶段值为 PreparingSnapshot/DerivingKey/Encrypting/Writing，不给 KDF 伪造百分比。取消使用调用协程的 Job，不另外设计无归属的全局 cancel 事件。

### 6.7 错误与通信数据规范

| 错误类别 | UI 处理 | 数据处理 |
| --- | --- | --- |
| ValidationError(field, reason) | 字段旁资源文案 | 不落库，不回显原密钥 |
| UnsupportedProtocol | 说明不支持类型，可手动输入 | 不调用外部 Intent |
| Locked/LeaseExpired | 遮挡并重新认证 | 清除返回值和缓存 |
| PermissionDenied | 手动入口或设置入口 | 释放相机 |
| DuplicateChallenge | 显示重复确认 | 暂不写入 |
| Conflict/SelectionChanged | 提示刷新选择/记录 | 不静默覆盖或少导出 |
| KeyUnavailable/CorruptRecord | 恢复说明 | 保留数据库，禁止新密钥覆盖 |
| OutputFailure/CleanupIncomplete | 提示失败及检查残留位置 | 关闭流，尽力删除 |
| Cancelled | 返回前一步或结束 | 不报告成功，不记异常日志 |

诊断日志仅包含稳定错误码、模块名和非敏感耗时，不包含账户 ID、名称、URI、口令、密钥、验证码、路径或异常中可能包含的输入。未知异常内部保留必要脱敏定位信息，UI 不直接展示 exception.message。

## 9. 安全、性能与测试实施

### 9.1 威胁边界

保护目标是共享密钥、导出口令、账户标识、当前验证码及导出文件。主要应对设备普通文件读取、系统备份复制、截图/日志泄漏、错误导出、生命周期竞态和不可信 QR 输入。不承诺抵御 root、恶意输入法、被攻陷 OS、同进程恶意代码或被用户主动交给第三方的明文备份。

Manifest 不声明 INTERNET，检查依赖合并结果而非只检查主 Manifest。关闭自动备份，并对旧版 backup_rules、新版 data_extraction_rules 的云备份与设备迁移分别排除数据库、偏好和内部敏感文件；厂商行为需实机验证。

本机 Keystore AES 密钥首版不绑定每次系统认证，避免不同版本凭据组合导致解密流程失效；应用锁通过门禁实现，文案不得宣称“每次解密均由硬件认证”。若后续改为认证绑定密钥，应新增 ADR 与升级恢复设计。

### 9.2 并发与线程模型

| 操作 | 执行位置 | 取消与资源 |
| --- | --- | --- |
| Compose/导航/系统提示 | Main | 宿主销毁解绑，迟到回调验证 requestId |
| QR 解码 | 独立有界执行器 | 最新帧优先，finally close ImageProxy |
| Room/文件 | 注入 IO dispatcher | 事务回滚、关闭流、不假报成功 |
| HMAC/序列化/KDF | 注入 Default 或受控计算 dispatcher | KDF 可能不可中途打断，前后检查取消并清理 |
| 前台 ticker | 会话作用域 | 后台撤销后停止，不建后台服务 |
| 剪贴板清理 | 有生命周期的应用任务 | 仅清除自己仍持有的条目，进程死后不保证执行 |

导出同一时刻只执行一个 CPU 密集 KDF，不能让快速点击排队占满线程。账户写入有互斥但不阻塞主线程；发给 UI 的结果验证会话 generation，避免取消后继续显示明文。

### 9.3 验证策略

- 单元测试优先于 UI 打通：RFC、时间、URI、Base32、重复确认、授权状态和文件格式先建立可执行约束。
- 密码学测试覆盖 ASCII 与中文/emoji 口令、不同 Unicode 组合序列、前后空白、API 24 与较新系统字节一致性。
- 导出以独立实现/固定向量交叉验证，不只做同一实现往返；测试解密器不等于产品提供恢复功能。
- 竞态测试覆盖锁定发生在快照后、KDF 后、输出前、输出中，及 Activity 重建后收到旧认证结果。
- SAF 使用可控测试提供方注入拒绝写入、部分写、close 失败和不支持删除；实机补充本地/云提供方。
- 性能原样采用需求指标：100 条生成 p95 ≤100 ms，认证后首屏 p95 ≤1 秒，边界更新 ≤1 秒，1000 条滚动超帧预算比例 <5%。固定 Android 10、4 GB、60 Hz 实体机，Release 至少 30 次采样，记录峰值内存与失败样本。
- api/impl/ui 检查同时扫描 Gradle 依赖和源代码 import，防止通过 app 或公共包意外暴露实现。所有目标检查任务建立后才纳入 CI 必过。

## 12. 待评审事项与剩余风险

1. 产品边界：确认明文导出和首版无文件恢复的限制可接受，导出界面必须说明。
2. 导出体验：SAF 往返重新认证与重新输入口令是后台锁定策略的直接结果；若要优化，需另行设计加密暂存方案并评审，不能放宽门禁。
3. URI 命名兼容：含冒号的名称可能无法无歧义明文导出；本文保留本地数据，明确失败并提供加密导出选择。此限制应回写需求评审结论。
4. 依赖验证：CameraX、ZXing、BC、Commons Codec、Room/KSP、Biometric 的具体版本尚未锁定或在本工程实测。
5. 格式校验：严格 JSON 重复键检测不能依赖默认覆盖式解析；后续恢复功能必须使用已验证的读取器。
6. 安全边界：系统提供方残留、厂商备份差异、JVM 内存副本和操作系统剪贴板都存在无法完全控制的边界，文案与测试报告须如实反映。
7. 性能指标：本文件定义实现与验证方法，无任何实测达标声明。
